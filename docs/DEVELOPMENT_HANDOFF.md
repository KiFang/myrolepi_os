# Передача смены: Rolepi

## Цель продукта
Настольное приложение для мастера: создать собственную TRPG-систему (любые типы объектов, параметры, формулы, карточки, действия) и вести по ней кампанию (герои, бой, заметки). Расширяется плагинами. Интерфейс для людей: простые термины, RU/EN, темы. Модуль лаунчера Asteia Alltools, но работает и автономно; само приложение не обновляется (обновления — лаунчер или вручную с GitHub).

## Что сделано
- **Ядро (`src/core`)**: кубики, формулы, схема системы (v1), вычисление параметров, валидатор, действия и инициатива (`actions.ts`), i18n, контракт плагинов. Ошибки ядра двуязычные (`messages.ts`, `setCoreLang`).
- **Студия** (`src/renderer/workspace/`): библиотека проектов (JSON-файлы), вкладки документов, отмена/повтор (80 шагов), сохранение, импорт/экспорт, сворачиваемые панели, нижняя панель «Проблемы / Журнал бросков».
- **Система**: типы, параметры, формулы, инициатива; вкладка «Карточки» — конструктор (сетка 12×N, ячейка 40px; перетаскивание и размер одним шагом отмены; виды, фон, 5 оформлений, блоки плагинов); вкладка «Действия» — формулы, вопросы при броске, эффекты.
- **Кампания**: «Герои» (форма/карточка, кнопки действий), «Карточки» (галерея, фильтр по категории = бестиарий), «Бой» (инициатива по формуле типа, раунды, ходы, быстрая правка ресурса), «Заметки» (поиск, связи с героями и заметками).
- **Оболочка** (`main.tsx`): шапка с разделами, выбор темы и языка (запоминаются), страницы Кубики / Формулы / Плагины / Справка / О программе.
- **Темы** (`themes.ts`): Ночь, Лес, Вино, Графит, Пергамент, День + темы плагинов. Весь CSS на переменных темы (`workspace.css`).
- **Плагины (API v1, расширен без поломок)**: функции формул (с описаниями для справочника), блоки карточек (HTML очищается в инертном `<template>`: `cards/sanitize.ts`), системы, переводы, темы, команды палитры, пресеты кубиков, настройки (форму рисует приложение), личное хранилище до 256 КБ. Загрузчик — `plugin-host.ts`: согласие пользователя по отпечатку кода (SHA-256) хранится в `app/plugins.json`, плагин вне согласия не выполняется; регистрации идут в черновик и переносятся только после успешного `activate` (таймаут 3 с); функции формул обёрнуты (ошибки с id плагина, проверка типа результата); имена `window/fetch/process/...` закрыты параметрами-заглушками. Это защита от ошибок, **не** граница безопасности. Управление — `usePlugins.ts` и `PluginsPage.tsx` (шаблон, примеры, запрос для нейросети). Примеры: `plugins/example-hello`, `plugins/example-extras`.
- **Палитра команд** (`CommandPalette.tsx`, Ctrl+K), **справочник** (`help/content.ts` — статьи RU/EN, `help/HelpPage.tsx` — поиск, таблица функций из реестра плагинов), **уведомления** (`toasts.tsx`), **анимации** (только opacity/transform, учитывают prefers-reduced-motion).
- **Миграция при переименовании параметра**: `core/formula.ts: renameVariable` + `workspace-model.ts: renameFieldInSystem/InCampaign`, один шаг отмены.
- **Сборка/релиз**: electron-builder (Windows/macOS/Linux), `.github/workflows/release.yml` (тег `v*`), лаунчер в `launcher/` (`lan-v*`).

## Карта кода
- `src/renderer/main.tsx` — оболочка. `tools.tsx` — инструменты. `lang.tsx` — язык. `strings.ts` — тексты студии (RU/EN; общие — `core/i18n.ts`, ошибки — `core/messages.ts`). `icons.tsx` — иконки (inline SVG). `fileio.ts` — импорт/экспорт.
- `src/renderer/workspace/`: `Workspace.tsx` (оболочка студии), `useLibrary.ts`, `SystemEditor.tsx` (+ `CardDesigner.tsx`, `ActionsEditor.tsx`), `CampaignEditor.tsx` (+ `CampaignGallery.tsx`, `CombatTracker.tsx`, `CampaignNotes.tsx`), `inputs.tsx`.
- `src/renderer/cards/`: `CardRenderer.tsx` (одна отрисовка для конструктора, галереи и листа героя), `themes.ts`, `sanitize.ts`.
- `src/renderer/workspace-model.ts` — создание документов, двуязычные значения по умолчанию, предпросмотр, проверки, `libraryProblem`.
- Логотип: `src/renderer/public/logo.svg`; иконка приложения `build/icon.png`.
- Терминология для пользователей: «игровая система», «тип», «параметр», «имя в формулах», «проблемы», «свойства». Не возвращать жаргон («сущность», «ID», «инспектор»).

## Проверка
`npm run typecheck`, `npm test` (юнит-тесты: ядро, действия, плагины, санитайзер, модель, примеры из гайда для нейросети), `npm run build`, `npm run e2e` (сценарии в браузере через `playwright-core`; `CHROME_PATH` задаёт Chromium), `npm run e2e:electron` (настоящий Electron под xvfb: аргументы лаунчера, согласие на плагин, запись на диск). e2e уже находили ошибки, которые юнит-тесты не видят (в Electron нет `window.prompt()`). Windows/macOS физически не проверялись.

## Версия 0.2.0: данные, обмен, защита, панели
- **Файлы и схема v2**: картинки — отдельные файлы с именем-хешем (`asset:<sha256>.<ext>`, `src/main/lib/assets.ts`, протокол `rolepi-asset://`); миграции `core/migrate.ts` + `renderer/migration.ts` (перед переносом — копия `before-migration`). Резервные копии: `src/main/lib/backups.ts`, страница «Данные» (`DataPage.tsx`). Главный процесс разбит на модули: `paths.ts`, `ipc-data.ts`, `plugins.ts`, `protocols.ts`, `main.ts`.
- **Обмен**: `.rolepi` — ZIP (`core/bundle.ts`, лимиты и проверка имён записей), логика в `renderer/exchange.ts` (`buildBundle`, `importData`), окно `ExportDialog.tsx`.
- **Защита систем**: `core/protection.ts` (подпись канонического JSON без `id` и `schema`), Ed25519 в главном процессе (`src/main/lib/keys.ts`, ключ `data/keys/author.json`). Защищённая система — только чтение (`Workspace.tsx`: `updateSystem` отклоняет правки, панель свойств в `fieldset disabled`). **Важно**: миграции защищённых систем не должны менять подписанное содержимое (схема в подпись не входит). Это не защита от копирования — только от подделки и указание автора.
- **Панели плагинов**: манифест `panels` + права `ui`, `project.read`, `project.write`. Страницы отдаёт протокол `rolepi-plugin://<id>/<путь>` (`protocols.ts`), только после сверки отпечатка всех файлов плагина с тем, что приложение показало в согласии (`main/lib/pluginFiles.ts`, `approvedHashes`); CSP страниц: `connect-src 'none'`, скрипты только свои. Рамка: `sandbox="allow-scripts"` без `allow-same-origin` (`PanelFrame.tsx`); связь — MessagePort, методы и права в `panel-bridge.ts` (чистый модуль, тесты `tests/panels.test.ts`). Запись в проект идёт через `change()` — работает отмена. Страницы подключают `@sdk.js`/`@sdk.css` из `panel-sdk/` (отдаются из любой вложенной папки). Размещения: `page` (раздел «Панели»), `right`, `bottom` (`Workspace.tsx`). Пример — `plugins/example-generator`.
- Проверки: `tests/panels.test.ts`, `e2e/panels.e2e.cjs` (браузер: изоляция, права, генератор), `e2e/electron.e2e.cjs` (настоящий Electron и протокол `rolepi-plugin://`).

## Версия 0.3.0: сцены, карты, звук
- Схема остаётся 2 (поля необязательные): `Campaign.scenes?: Scene[]`, `Campaign.maps?: GameMap[]` (`core/schema.ts`). Метки карт — доли размера картинки (0…1); карты — ссылки `asset:…` (входят в бандлы и копии автоматически). Музыка и звуки сцены — ссылки `music/<путь>` и `sounds/<путь>` (`core/audio.ts`), сами файлы в бандл не входят.
- Звук: папки `dataDir/audio/{music,sounds}` (`src/main/lib/audioLib.ts`, `ipc-audio.ts`: список, слежение `fs.watch`, событие `audio:changed`), протокол `rolepi-audio://<music|sounds>/<путь>` с поддержкой Range (`protocols.ts`; пути проверяются `resolveAudio`: без `..`, скрытых частей и ссылок за пределы папки). Плеер — один на приложение (`renderer/audio/engine.ts`, затухание при смене трека, очередь, повтор, перемешивание), страница `AudioPage.tsx`, мини-плеер в шапке.
- Сцены и карты: `workspace/CampaignScenes.tsx`, `CampaignMaps.tsx`, `MapCanvas.tsx` (перетаскивание меток через pointer events с `dragRef`, стрелки на клавиатуре). Переходы по меткам: `ed.openTarget`. Удаление героя, заметки, карты и сцены чистит ссылки.
- Проверки: `tests/audio.test.ts`, `e2e/scenes.e2e.cjs` (браузер, звук проверяется настоящим WAV), `e2e/electron.e2e.cjs` (протокол, Range, закрытые пути).
- Windows: в 0.1.0 и 0.2.0 сборка под Windows падала на тестах руководства (CRLF). Теперь тесты нормализуют переводы строк, добавлен `.gitattributes`. При новых тестах читать файлы проекта через нормализацию или не зависеть от `\n`.

## Версия 0.4.0: шаблоны, бестиарий, простой режим, скорость
- Шаблоны: `src/renderer/templates.ts` — `FIELD_PRESETS` (≈45 готовых параметров по группам), `TYPE_TEMPLATES` (персонаж, существо, корабль, поселение, предмет, место, фракция), раскладка карточек `buildBlocks`/`appendToView` (блоки не накладываются, тест в `tests/templates.test.ts`). Меню — `workspace/PresetMenus.tsx` (+ `Popover.tsx`: панель через портал в `.workspace`, `position: fixed`, помещается в окно, раскрывается вверх, если внизу тесно; нельзя без портала — предки с transform ломают fixed).
- Бестиарий: `GameSystem.bestiary?: BestiaryEntry[]` (`core/schema.ts`), редактор `workspace/BestiaryEditor.tsx`, форма значений вынесена в `workspace/EntityForm.tsx` (общая с героями), добавление в кампанию — `ed.addFromBestiary`. Защита/подпись/пакеты покрывают его автоматически; удаление типа чистит его записи; проверка ядра предупреждает о записях без типа.
- Простой режим: `renderer/simple.tsx` (контекст + localStorage `rpi.simple`), переключатель в шапке; прячет формулы, имена в формулах, действия, страницы «Формулы/Плагины/Данные» (в меню и в палитре), инициатива — выбор из списка. Советы: `renderer/tips.tsx` (список `TIPS` по местам, закрытые хранятся в `rpi.tips`).
- Скорость: страницы и тяжёлые части подгружаются (`React.lazy`: Звук, Плагины, Данные, Справка, калькуляторы, конструктор карточек, диалог экспорта, пример системы, `exchange`/`fflate`), `vite.config.ts` — `target: chrome130`, окно показывается по `ready-to-show`. Замер: `node e2e/startup.cjs 5` (настоящий Electron под xvfb; при замере убивайте процесс группой — иначе остаются «осиротевшие» Electron и замер врёт).
- Исправлено: гонка плеера (остановка во время затухания запускала следующий трек), шапка при ширине ≈1250 px.

## Ограничения и что делать дальше
- Код плагинов `index.js` (формулы, блоки, команды) — доверенный (`new Function`), не песочница: защищают согласие, отпечаток кода и закрытые имена. Реальная изоляция — только у панелей. Панели с формулами пока не связаны.
- Нет экспорта карточки в PDF/картинку, ссылок `[[заметка]]`.
- Дальше по плану: общий пакет ядра (монорепозиторий), шаги создания персонажа, приложение Rolepi Chartool, каталог открытых систем (только открытые лицензии, по желанию пользователя), лаунчер — в отдельный репозиторий, когда проектов станет больше.
- Лаунчер: интерфейс минимальный, дизайн отложен.

Не менять стек и не переписывать ядро ради новой функции. Начинать смену с `git status`, чтения этого файла и актуальных инструкций; не затирать чужие незакоммиченные изменения.
