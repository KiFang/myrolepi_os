# Передача смены: рабочее пространство MyRolePi OS

## Цель продукта

Профессиональное настольное приложение для создания собственных TRPG-систем и ведения кампаний. Ориентир по организации интерфейса — редакторы Adobe и Office: дерево проекта, документы, центральный редактор, инспектор свойств, панели диагностики. Сохраняем универсальную модель правил и поддержку плагинов. Пользователь разрешил продолжать реализацию по нашему усмотрению в рамках этой идеи; согласовывать стек заново не требуется.

## Сделано в текущей смене

- Стартовый экран заменён рабочим пространством: библиотека систем/кампаний, вкладки документов, команды сохранения, отмены/повтора, инспектор и диагностика.
- Редактор системы: название, версия, описание, добавление типов сущностей, категории, добавление/удаление полей, ID, тип, группа, формула, значение по умолчанию, пределы, варианты select и refType.
- Предпросмотр значений с существующим движком, макросами и функциями установленных плагинов. Для стабильного предпросмотра RNG фиксирован на 0.5; это не настоящий бросок.
- Кампания привязана к системе: создание сущностей, редактирование значений, пересчёт вычисляемых полей, заметки ведущего.
- Системы и кампании читаются/пишутся через существующее JSON-хранилище Electron (`systems/`, `campaigns/`). Ошибка открытия блокирует редактирование библиотеки; ошибка записи оставляет документ несохранённым.
- Undo/redo хранит до 80 состояний в памяти. Сохранение фиксирует именно записанный снимок: последующие изменения остаются несохранёнными. Удаление ранее сохранённого документа через undo отражается в хранилище при следующем сохранении (`store:remove`). Запись отдельного JSON атомарная; сохранение всей библиотеки не является общей транзакцией.
- Ctrl/Cmd+S сохраняет библиотеку; Ctrl/Cmd+Z и Shift+Z вне текстовых полей управляют историей проекта. В текстовых полях остаётся нативная отмена. При закрытии/перезагрузке с несохранёнными изменениями Electron предлагает продолжить редактирование или закрыть без сохранения.
- Прежние кубики, песочница формул, просмотр систем плагинов, справка и список плагинов доступны из верхней панели. Рабочее пространство остаётся смонтированным при переходе к инструментам, поэтому черновики сохраняются в памяти.

## Обновление интерфейса по примеру Facet OS

- Добавлены векторный знак MyRolePi и единый набор SVG-иконок без новых зависимостей.
- Создание системы теперь проходит через модальное окно: имя, базовая TRPG/чистый лист/космическая опера/система плагина. Отмена не создаёт документ; шаблоны копируются независимо от источника.
- Базовый шаблон содержит Силу, Ловкость, Выносливость, Уровень и вычисляемое здоровье. Все правила редактируемы.
- В редакторе показана последовательность «структура → формулы → кампания». Кнопка третьего шага создаёт кампанию по открытой системе.
- Настройки выбранного поля подняты в инспекторе; настройки документа/типа сворачиваются в details. Простые значения по умолчанию вводятся обычными контролами, JSON оставлен для составных данных.
- Исправлены горизонтальное переполнение кампании и нечитаемый текст нативных select в headless Electron: StudioSelect сохраняет нативный select, а выбранный текст отображает отдельным слоем.
- Проверены мастер, вычисления кампании, сохранение/открытие, отмена мастера и отсутствие горизонтальной прокрутки canvas при ширинах 1280/1024/900. Снимки сделаны из работающего Electron.

## Где продолжать

- `src/renderer/workspace.tsx` — оболочка, редакторы и история/сохранение. По мере расширения разделить на отдельные компоненты и вынести хук документов.
- `src/renderer/workspace-model.ts` — создание документов, локализованные названия, безопасный предпросмотр и проверки полей.
- `src/renderer/create-system.tsx`, `src/renderer/studio-ui.tsx` — мастер создания системы, логотип, иконки и единые select.
- `src/renderer/workspace.css` — стили профессиональной оболочки.
- `src/main/main.ts`, `src/main/preload.ts` — удаление JSON и предупреждение о несохранённых изменениях.
- `tests/workspace.test.ts` — вычисления с вводом кампании/плагинами, циклы и неизвестные зависимости, ID/пределы и сохранение переводов при редактировании.

## Проверка

`npm run typecheck`, `npm test`, `npm run build`. После обновления интерфейса проходят 27 тестов приложения. Electron проверен на Linux под локальным Xvfb с `--no-sandbox`, поскольку облачный контейнер не поддерживает Chromium sandbox. Тестовые данные отдельно от пользовательской библиотеки.

Функциональный сценарий: создать систему, добавить `strength` (default 10) и `hp` (формула `strength * 2 + 5`), получить 25; создать кампанию, добавить персонажа, задать силу 16, получить 37; добавить заметку, сохранить и открыть повторно. Проверены восстановление имени, исходных значений, вычисленного HP и текста заметки. Проверки интерфейса используют Playwright CDP; для текстового ввода в виртуальном дисплее использованы DOM input-события, поскольку обычный CDP insertText в этом окружении не всегда вводит текст. Физический ввод на Windows/macOS ещё проверить.

## Честные ограничения текущей версии

- Новая оболочка пока на русском; прежние инструменты сохраняют RU/EN. Редактирование переведённых названий обновляет только русский перевод, остальные сохраняются.
- Лист кампании сейчас автоматически строится из полей; произвольная раскладка, темы/фоны и карточки ещё не реализованы.
- Reference/image пока редактируются как текстовые значения, resource — как число или исходный JSON-объект. Нужны специализированные редакторы и правила валидации значений.
- Нет редакторов действий, таблиц и макросов; существующие данные сохраняются и макросы исполняются.
- Нет карт/связей мира, сцен и трекера боя, импорта/экспорта проектов или PDF, закрытия вкладок и удаления библиотечных документов отдельной командой.
- Плагины по-прежнему доверенный код через существующий host; изоляция Worker/iframe не добавлена, нельзя называть текущий механизм безопасной песочницей.
- Переименование ID показывает сломанные ссылки в диагностике; автоматическая миграция ссылок и значений кампаний ещё не реализована.
- Схема данных остаётся v1. До изменения формата понадобится стратегия миграций/резервных копий.

Не переписывать рабочее ядро и не менять стек ради следующего этапа. Начинать смену с `git status`, чтения этого файла и актуальных инструкций; не затирать незакоммиченные изменения предыдущей смены.
